# The two sources the request named (2026-10-30)

**fr.wikipedia.org/wiki/Btrfs** (raw wikitext fetched). Copy-on-write B-tree file system (Rodeh's design, Mason at Oracle), stable
since Linux 3.10; checksums, snapshots, subvolumes; compression zlib, LZO and, since 4.14, zstd; 255-byte names, 16 EiB limits.
What it implies here: the reader must handle all three compressions (two done, roadmap 0013), subvolumes (done), and checksums (metadata
done, data roadmap 0015).

**github.com/ninerf/NTFS-C** (cloned, `ntfs.c` read). A 400-line C tool that finds NTFS volumes through Disk Arbitration, unmounts the
system's read-only mount and remounts with ntfs-3g over macFUSE; it documents the Reduced Security steps macFUSE's kernel extension
needs on Apple Silicon, and handles hibernated and dirty volumes. What it implies here: the kernel route costs the user a security
downgrade, which is the argument for FSKit (ADR-0005); its Disk Arbitration flow is the model for roadmap 0021; its hibernation and
dirty-volume handling is a requirement for any NTFS write path (roadmap 0017).
