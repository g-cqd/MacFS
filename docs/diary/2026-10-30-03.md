# Diary — 2026-10-30 (03)

## First mounts (roadmap 0005)

The owner enabled the three modules in System Settings. Then, as the user, no sudo:

| Claim | Probe | Verdict |
|---|---|---|
| An enabled module mounts an attached image | `mount -F -t btrfs -o rdonly /dev/disk18 …` | Holds: `(btrfs, local, nodev, nosuid, read-only, noowners, noatime, fskit, mounted by gc)` |
| The kernel sees the same tree the reader tests see | `mount-compare.py` against each manifest | Holds for all eleven images: 0 differences |
| Writes are refused | `touch` on each mount | Holds: "Read-only file system" |
| An unsupported extent fails loudly | `head` of a zstd file | Holds: "Operation not supported", other files read |
| NTFS lookup is case-insensitive through the kernel | `cat HELLO.TXT` | Holds |
| Attached images mount on their own | `hdiutil attach -readonly ext4.img` | **REFUTED**: "no mountable file systems" (roadmap 0024) |

`diskutil info` on the NTFS image names Apple's own NTFS personality (`Type (Bundle): ntfs`): Disk Arbitration's probe is the system's,
while the mount is ours. Whether that matters for 0024 is open.
