## Writes through the NFS proxy, and a race the client exposed (roadmap 0046)

| Claim | Probe | Verdict |
|---|---|---|
| The proxy answers RFC 1813's changes through the writer | six RPC-level tests on the ext2 writer, each ending with e2fsck | Holds; mutants (no ISDIR check, an exclusive create ignoring its verifier, ACCESS without modify) each caught |
| A writable proxy mount writes | `macfs-nfsd ext2.img --mount DIR --writable`, then the write check's operations through `mount_nfs` | **REFUTED** at first, silently: `cp` of 4 MiB exited 0 and kept 917,504 bytes; `dd` of four 128 KiB writes kept three |
| The ext writer is safe under concurrent callers | 16 threads writing one file, 24 creating in one directory | **REFUTED**: sizes and blocks lost, e2fsck failed. macOS's NFS client keeps several WRITEs in flight; two changes each read, grow and write back one inode. FSKit had called serially |
| Serializing every change fixes it | the two tests, then the live session again | Holds: 4 MiB copied and compared, every operation, then e2fsck -fn clean and debugfs's hashes equal to the host's for the moved, linked and appended files |
| The descriptor tests are independent of the others | the whole suite, in parallel | **REFUTED** once: a process another test spawned (the checkers' container) inherited a probe's pipe, which then never read as closed. The probes' pipes are close-on-exec now |

The lock (`ExtFileSystem.changeLock`, a plain `Mutex`: no change calls another) wraps the thirteen public changes; reads stay
unlocked and may see a change in progress, as with any file system without page locking. `changingName` now holds the start
every name change shares. The FSKit check after the rebuild: 38 of 38.
