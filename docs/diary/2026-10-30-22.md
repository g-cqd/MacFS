# Diary — 2026-10-30 (22)

## Everest on the roadmap, and the NFS proxy hardened by its findings

Everest read at the code (research 2026-10-30-everest-code-review): 22 features, each with what MacFS does better and its entry.
ADR-0013 (one mount seam, a persisted registry, make before break, no silent substitution, proxy mounts owned by a launchd agent,
the lifecycle in TLA+); roadmap 0035, 0036 and 0008 amended, 0038 to 0044 new. The owner then asked for writes on every format
(0017 now tables them; 0045 XFS writes and 0046 writes through every mount path are new) and a study of promoting MacFS's kernels
to aemi (research 2026-10-30-promoting-to-aemi, roadmap 0047).

| Claim | Probe | Verdict |
|---|---|---|
| A dead proxy hangs its mount, as Everest's WebDAV volumes did | `man mount_nfs`; `macfs-nfsd`'s printed options | Holds for the old command (hard). Now soft with `deadtimeout=10`: after `kill -9`, `ls` failed "Operation timed out" in 8 s and the kernel removed the mount in 19 s |
| A secret export path keeps other local users out | the mount table | **REFUTED**: `mount` shows `127.0.0.1:/macfs-…` to everyone once mounted (Everest's token URL too). The export admits one MNT and handles carry a secret; a second `mount_nfs` was "Permission denied", `/` "No such file or directory" |
| Answering a connection's calls concurrently is faster | bench images through `mount_nfs`, in order against concurrent | **REFUTED** at first: Btrfs lost a fifth. `BoundedCache.value` made a missing key in every concurrent caller, so eight READs of one MiB verified it eight times (a test read 8.4 MB). With misses made once: level on ext4 and plain Btrfs, compressed text 2.1 times |
| The client's read size is right | `rsize` 32 KiB (default) against 128 and 512 KiB | **REFUTED**: 128 KiB, the proxy's FSINFO preference, reads 1.4 to 1.6 times faster; now in the mount command |
| The limits hold | `LoopbackLimitsTests`: idle, cap, a client that stops reading, a slow call, 32 large replies at once | Holds; mutants (one call at a time, cap plus one) went red |
| The tests see every change to the new code | 239 mutants (export, mount command, MOUNT, handles, server limits, `BoundedCache`, Btrfs verify) | **REFUTED** at first: 94 of 183 compiled ones survived. New tests: hex of high nibbles, the AUTH_UNIX flavor, ADR-0014's numbers, a stopped server, a closed connection's place, a hang-up and a reset, a record a byte at a time and at 2 MiB, MNTPATHLEN, a pausing reader (XNU's send timeout runs per wait, so only a pause between one and two timeouts makes a write partial), the eviction half, later Btrfs pieces through two adjacent extents. 147 killed, 36 equivalent survive (socket option values, fd 0, EAGAIN equal to EWOULDBLOCK on Darwin, stale errno at EOF, buffer sizes, padding of short UUIDs, an overwritten fill) |
| Clones are enough to run the Btrfs suite | the harness's clones | **REFUTED**: they lacked `TestCorpus`, so every mutant "died" on the zstd corpus tests; linked, rerun |
| The proxy's tests are steady | twelve runs | **REFUTED** at first: one in six died of SIGPIPE in the test client (a server that closes first); the client sets `SO_NOSIGPIPE` |

Not verified: the hard-mount hang was not reproduced (it can wedge Finder for the session; the man page is the source); the
mount agent, registry and TLA+ model are planned, not built; the adversarial suite for the proxy is open; harnesses live in /tmp
(`nfsbench.sh`, `swiftmut2.py`).
