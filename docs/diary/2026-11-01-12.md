# Diary — 2026-11-01 (12)

## The write ADR, the writable device and the crash recorder (roadmap 0017, ADR-0018)

ADR-0018 accepted, from the FSKit probes (diary 11) and the container's checkers. Then the foundation every format's writer
shares:

- `WritableBlockSource` (`write(at:_:)`, `flush()` as a barrier); `MemoryBlockSource`; `FileBlockSource` opened writable,
  through aemi's `PosixFile` (`pwrite`, `sync(.full)`, F_FULLFSYNC); `DiskError.readOnly` (EROFS).
- `CrashTesting.CrashRecorder`: records writes and flushes; its crash states are the image before any write, as of each flush,
  at the end, and inside each epoch its proper subsets (exhaustive up to a bound, then each write alone, each but one, each
  prefix). States are overlays: no image is copied.

| Claim | Probe | Verdict |
|---|---|---|
| A raw device takes any write | `dd` of 1 byte, then 512, to a user-attached image's `/dev/rdisk` | **REFUTED**: 1 byte is refused; the device path reads, patches and writes whole sectors (live test: 3 bytes at 1000 kept the rest of the sector) |
| An epoch of two writes can be sampled | the boundary test | **REFUTED**: the inner-prefix range `2 ..< 1` traps; sampling starts at three writes |
| States need de-duplicating | a mutant removing it survived | No: the generation never repeats a set of writes; the de-duplication hid a prefix mutant, and went |
| A state reads correctly away from a write | a read starting after a write | It trapped (a negative range) under a mutant no test caught; test added |
| The live device test cleans up | `hdiutil info` | **REFUTED**: the test's open descriptor made the detach fail, twice; the source now closes first and a `defer` force-detaches |
| `NFSStatus.of` needs its own switch | dolly (a clone of the volume's mode switch) | No: RFC 1813's statuses are the POSIX numbers but NOTSUPP; derived from `posixCode`, every case pinned by a test first |

Also: my mutation harness assigned the global `F` I also used for a file path, so two mutants reported "no match"; it uses a
