## The live write check, and the append it caught (roadmap 0046)

After a restart (the processes stuck in the kernel since diary 2026-11-01-18 gone), the mount check: 18 of 18 FSKit mounts,
ext2's included; the agent path failed until the app registered its agent again, then 36 of 36.

`macfs-tool mounts` now ends with a writable session per writable format (`WriteCheck`, ext2 for now): the image copied with
its own UUID, attached writable, mounted through FSKit without `rdonly`, changed by subprocesses with deadlines, released, then
judged on Linux in the checkers' image (`e2fsck -fn`, `debugfs` dumps hashed against the host's SHA-256). The tool starts the
container system only if it is down, and stops it at exit if it started it.

Red first: `aRangeMappedBeforeTheLastWriteCompletedKeepsThatWrite` maps and writes a second range before completing the first,
and read the first's tail as zeros. After the fix: 37 of 37 live, the write check included. The write check's own tests were
each seen failing by breaking what they guard (an operation's failure not stopping the rest, a failed mount still checked, a copy
keeping the image's UUID).

`MountSession` now holds what both FSKit checks do around their work (attach, mount with the helper retry, unmount, detach);
an unmount failure is now a problem for the read check too.
