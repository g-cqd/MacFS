# Diary — 2026-11-01 (08)

## Commands with deadlines: swift-subprocess (roadmap 0048, ADR-0017)

The owner asked whether swift-subprocess had been looked at. It had not: everything ran through `Process`, with no deadline.

| Claim | Probe | Verdict |
|---|---|---|
| Our own deadline over `Process` is as good as the library | the same four commands through both (research 2026-11-01-commands-with-deadlines) | **REFUTED**: after SIGKILL, an orphaned grandchild held the pipe (4 s instead of 2) and kept running; `Process` cannot give the child its own group |
| swift-subprocess's output limit keeps a chatty command's status | `.string(limit:)` on 50 MB | **REFUTED**: it throws and the status is lost; streaming with our own cut-off keeps it |
| `Process` leaks the agent's descriptors to commands | a pipe without CLOEXEC, `ls /dev/fd` in the child | Refuted, for both |
| My first grandchild test was red for the right reason | it ended in 0.35 s | **No**: `sleep 30 marker` is an invalid call to `sleep`. The marker became an inner shell's `$0`, after which the test waited the full 30 s on the old runner |
| A mutant that didn't compile counted as a survivor | `[output, output]` | warnings are errors, so the old build ran; rewritten so it compiles, it was killed |

Red: 4 of 5 tests failed on the old runner given the new initialiser (30 s waits, unbounded output). Green: 7 tests. 10 hand
mutants killed (process group, group teardown, the graceful step, cancellation, the deadline, the cut-off, the signal status,
standard error, the not-run status, the message). The runner sits in its own target: the agent grew by 841 KB, and the four
modules carry no Subprocess symbol. Live: install, FSKit 18/18, agent 18/18.

Not verified: a hung `umount` in the agent itself (0048 step 3); a command stuck in the kernel.
