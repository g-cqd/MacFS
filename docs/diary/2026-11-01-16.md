# Diary — 2026-11-01 (16)

## ext2 rename and hard links; how much of this carries to the other formats (roadmap 0026 step 3)

| Claim | Probe | Verdict |
|---|---|---|
| A directory move has an order preen repairs | every crash state of a move to another parent | **REFUTED**: "is a link to directory" (two names) or "'..' … should be …" in 98 states, both orders; only `e2fsck -fy` repairs them, as on Linux's ext2. ADR-0018 now names this case |
| A rename within a directory need not have that window | the same states, both names in one block | Holds: removed and inserted in one write, every state preen-clean |
| The subtree test tested the subtree rule | its failure | **REFUTED**: `dir/sub` is indexed, refused before the rule; the test uses a linear subdirectory |

The owner asked whether this generalizes. Format-independent already: ADR-0018, the writable device and its flush barrier,
the cache invalidation, the crash recorder and its states, the checkers' runner, `WritableFileSystem` and its errors; FSKit and
the NFS proxy will write through the seam once for every format. Per format: what changes on disk (bitmaps or B+trees,
directory forms, crash mechanism). Candidates for sharing when a second format needs them: a bitmap allocator (ext, NTFS's
`$Bitmap`), a B+tree editor over a node format (XFS's trees, NTFS's indexes).

`remove` now gives up its node through the same `giveUp` a replacing rename uses, and create, rename and link add names
through one `addName`.
